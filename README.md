# 群聊控制

独立的 AstrBot QQ 群控制插件：每群分别设置发言总开关、总回复额度、读空气回复额度及生图权限。支持搜索、批量开关和用量查看，不需要模型 API，也不依赖模型路由或 Chat Plus。

[更新日志](CHANGELOG.md)

## 安装和入口

适用于 **AstrBot 4.29.3 + OneBot v11 / NapCat**。

1. 在 AstrBot 插件页通过本仓库地址安装并启用；已有安装可直接更新，保留配置与运行数据。
2. 刷新后台，从左侧 **插件视图 → 群聊控制** 打开面板；也可以从插件详情的视图组件进入。
3. 群发言总开关点击即保存；两项回复额度修改后点击 **保存回复额度**，即时生效，无需重载。

使用 AstrBot 内置的 [插件视图](https://docs.astrbot.app/dev/star/guides/plugin-pages.html) 与后台登录权限，不另开服务、端口或账号，也不注册 QQ 管理命令或模型工具。

## 从原路由插件迁移

**路由 v0.5.11 → v0.5.12：**先更新并重载群控至 **v0.4.0**，导入旧限额，再更新并重载路由。旧 `reply_limit_*` 只转成读空气额度，**总额度默认关闭**；旧免冷却群转成“跳过 Chat Plus 冷却”，两项额度默认关闭。已有群开关和生图设置保留，后续启动不覆盖已迁移或手动保存的设置。新版路由会删除旧配置项，请在迁移后再保存新版路由配置。

例如原大群 `3600 秒 1 次`，迁移后仍是读空气最多一小时主动回复一次，直接 @不消耗该额度。没有安装路由时，两项额度默认关闭，可在面板自行设置。

仅当你已使用「证据问答与会话路由 v0.5.7」内置面板时需要此步骤：

1. 将原路由插件更新至 **v0.5.8** 并重载。旧版含有内置群控时，本插件会提示升级，避免双重开关冲突。
2. 启用本插件。首次启动自动复制旧 `plugin_data/astrbot_plugin_evidence_qa/group_switches.json`，旧文件不改动。
3. 在独立面板检查原来的群开关。已有独立状态时，后续启动不再读取或覆盖旧状态。

不要先卸载旧插件并删除数据；直接更新即可。迁移期间需要持续静默的群，可以先在原生「自定义规则」暂时停用，完成迁移后恢复。没有安装原路由插件的用户可以直接使用本插件。

## 面板操作

| 操作 | 效果 |
|---|---|
| 点击单群开关 | 立即开启／关闭该群发言，并保存 |
| 勾选多个群，点击开启／关闭选中 | 一次保存全部选中群的状态 |
| 搜索群名、群号或平台 | 过滤列表；已勾选的群仍参与批量操作 |
| 刷新群列表 | 重新读取 QQ 群名和群号，不改变开关 |
| 添加群号 | 为尚未出现在群列表的群登记开关，登记时先关闭 |

初始状态默认放行，不改变原有行为。状态按平台实例与群号区分，保存在 `plugin_data/astrbot_plugin_group_control/group_switches.json`，重启或升级后保留。首次打开面板读取群列表，以后手动刷新；不定时轮询、不调用模型。

## 总回复与读空气额度

| 设置 | 计数范围 |
| --- | --- |
| 总回复额度 | 本群全部回答轮次，包括直接 @、关键词、读空气接话和后台主动回复 |
| 读空气回复额度 | 未直接 @机器人的回答轮次，包括普通接话、关键词智能触发和后台主动回复 |
| 跳过 Chat Plus 冷却 | 取消 GCP 密度、疲劳、注意力冷却；仍保留概率和是否接话判断，不豁免上面两项额度 |

每项额度都有独立开关、**窗口（秒）**和**最多（轮）**。关闭某项表示该项不限。主动接话同时计入两项，直接 @只计入总额度。若希望直接 @一直可答，关闭总额度，仅开启读空气额度。

一条用户消息的多段文本、图片与后续配文合计一轮，不按气泡数扣减。成功发送才计数；生成中先占名额，未回复、发送失败或取消会释放。面板显示已用、进行中和下一轮额度恢复时间；**刷新用量**不调用模型，也不重新拉取 QQ 群列表。

达到额度后停止本轮回复，不排队补发。真实 @标记在消息改写之前记录；@其他人、@全体、正文中的“@Tia”、引用里的 @不作为直接 @。主人注册管理指令和已识别的暂停／恢复指令豁免额度，群发言总开关仍优先。黑名单、原生权限和独立按ID限制继续有效。

计数使用滑动窗口，从成功发送时开始，不在整点重置。设置持久保存；**回复计数保存在内存，重载群控或重启 AstrBot 后重新统计**。已开始发送的一轮可完成剩余分段；关闭发言总开关仍可截断后续分段。

## 生图开关与张数

每张群卡片可以分别设置：

| 设置 | 用法 |
|---|---|
| 允许生图 | 关闭后拒绝本群新的生成请求，在调用生图 API 前检查；默认开启 |
| 生图配文 | 默认关闭。自动生图只发送图片，去掉调用前承诺、图旁点评和重复尾句；真实失败仍会提示 |
| 单次上限 | 同一条用户消息最多生成多少张，包含批量任务及多次工具调用；`0` 不限 |
| 周期（分钟） | 滚动统计窗口，例如 `30` 或 `60` |
| 周期上限 | 该群整个窗口内的总张数，所有成员共用；`0` 不限 |

例如：单次 `1`，周期 `60`，周期上限 `3`，表示每条消息最多一张、全群任意连续一小时最多三张。两个上限初始均为 `0`，由你按群填写。开关点击保存，数字修改后点击 **保存限额**。发言总开关保持最高优先级，原生权限及其他插件的用户权限、冷却规则继续生效；允许生图并不授予管理权限。

配文开关只作用于实际执行生图工具的轮次，普通「这张图是什么」「评价这个表情包」照常回答。仅对 QQ 群生效，私聊、创作台和论坛发帖模式保持原流程。原生 `/生图`、`/改图` 等命令受生图开关与张数约束，但它们自身的准备进度提示不属于 LLM 配文。

计数保存在 `plugin_data/astrbot_plugin_group_control/image_usage.json`，仅包含群标识、时间和张数，不记录提示词或图片。进行中的请求先占位，已确认失败释放，部分成功按实际张数结算；重启时无法确认结果的未完成请求保留原占位数。关闭生图不撤销已经交给供应商的任务。配文关闭时，前台结果与后台结果均直接发送，不再另调聊天模型撰写点评。

当前适配 **AstrBot 4.29.3 + `astrbot_plugin_gemini_image_generation` v3.2.0**，启动日志会显示「生图权限、张数和纯图片交付已接入」。本插件对这些版本的生成入口和 Agent 响应入口做运行时适配，升级内核或生图插件后需要重新验证。没有加载兼容生图插件时，面板会提示未接入，设置仍可保存。

## 与其他插件的关系

发言必须同时满足：**本面板允许 + 原生消息处理允许 + 其他触发、权限和限流规则允许**。

- 关闭时，主人、@、关键词、免冷却群均不豁免；私聊不受影响。
- 开启后，保留 Chat Plus 接话判断、主人暂停和本面板的回复额度、按 ID 回复限额等规则，不清空这些规则的状态。
- 不修改原生白名单、模型、人设、知识库或其他插件配置。
- 如果原生「自定义规则 → 消息处理」已关闭，需要在那里恢复一次；面板显示提示，不擅自覆盖。
- 路由插件、Chat Plus 都不是必装项；安装或卸载它们不改变本插件的持久权限。

## 基于原图修改

搭配 **Gemini Image Generation v3.2.0** 使用。在 QQ 群中发送图片并说「基于这张图画一个流泪版」，或随后说「把上一张图改成黑白」即可。也可引用某条图片消息明确选择原图。

- 当前附件或引用的图片直接传给生图接口，模型漏填参考图参数也会补齐。不会用看图后的文字描述替代原图。
- 「上一张图」只取同一平台、同一群、同一用户最近发来的图或为其生成的图；其他成员插入图片不会替换它。多图消息中未指定序号的「上一张」指最后一张。
- 编辑提示词使用用户原话，要求保留未指定修改的外观，不采用聊天模型擅自扩写的衣服、发色或结构。批量任务附带任务序号；绘图模型仍负责理解并执行这些要求。
- 原图缺失或读取失败时返回明确错误，请重发或引用图片。OpenAI Images 必须允许图片编辑；供应商启用 `generations_only` 时不静默丢弃参考图。
- 原图在请求构建前按内容去重；日志记录来源、张数、摘要及 `images/edits`，不记录图片内容。

最近图片的来源记录保存在 `plugin_data/astrbot_plugin_group_control/image_references/recent.json`，最多 256 个用户与群的组合。只在需要编辑时读取原图；成功读取后缓存原始字节，总量上限 256 MiB。无需额外模型调用，不会为群里每张图片自动下载或识别。临时 QQ 链接过期且无法恢复时仍需重发。停用或升级不清空群权限；私聊保持原有生图插件流程。

## 群发送拦截

新群消息在进入处理前检查；事件回复、图片、合并转发、群文件、戳一戳，以及经过 AstrBot OneBot 客户端的主动发送，在发送前再次检查。Chat Plus 的独立主动生成另有开始前检查，保持原有模型与接话判断。

关闭时已经开始处理的事件回复会失效，重新开启不会补发旧回复；已发送分段的剩余部分会被阻止。保存失败不会先改变内存权限。关闭时依赖新消息事件的其他插件处理也会停止，不删除已有历史或记忆。

已经交给 NapCat／QQ 的发送请求不会撤回。绕过 AstrBot 客户端、独立连接 NapCat 的其他程序不受本插件控制。停用或卸载本插件后不再提供拦截。
